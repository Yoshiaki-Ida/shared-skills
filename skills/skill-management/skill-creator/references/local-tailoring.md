# ローカル差分

Anthropic版の作成→比較評価→人間の確認→改善を基本にする。以下は、この環境に必要な追加・上書きだけである。

## 1. 原本と既存Skill

- 作成前に対象リポジトリのREADMEのSkill一覧、既存のSkill・Agent・常時指示を確認する。用途カタログがある場合はそれも使う。同じ責務なら既存Skillを拡張し、不要な重複を増やさない。
- 原本と配布コピーが分かれている場合は原本を編集する。配備先だけを正本にしない。ユーザー指定を優先し、候補が複数で結果に影響する場合は確認する。
- 公開版・private版・個人配備先を混同しない。今回承認された範囲を明記し、配備・コミット・pushは別の操作として扱う。依頼済みの操作を再質問しない。

## 2. 質問ゲート

作成または実質的に更新するSkillにも、次の意味を組み込む。

- 結果・対象範囲・安全性・データ更新・成果物に影響する不明点は、依存する処理を始める前に質問し、回答を待つ。
- 判明済み事項、不明点、必要な回答を示し、回答後は確認済みの入力と完了工程を保って再開する。
- 既存仕様・確認済み入力・明示済みの既定値で決まる実装詳細は質問しない。
- 推測・代替・フォールバック・モード変更・範囲変更・成果物の省略を、不明点の解消として勝手に行わない。
- `null`・`unknown`等が正規の出力なら、その利用を推測と扱わない。ただし依頼された成果物や範囲が変わる場合は確認する。

質問に依存しない調査は続ける。評価の実行環境が不足する場合も、Skill原文の整備・ローカル形式検証など独立して進められる作業は完了する。

## 3. 評価の範囲と実行環境

- 原文の比較評価を使う前に、対象ケース・比較対象・実行環境を整理する。単なるSkill編集の依頼を、外部AI/CLIの利用や大量の比較実行の許可へ広げない。評価がすでに明示依頼され、条件が確定していれば再確認しない。
- 新規Skillは「Skillなし」、更新は「旧版」と比べる。旧版を退避し、同じ入力・評価基準を使う。評価件数と反復回数は依頼された範囲に限定する。
- Claudeで原文の評価を実行する場合、CLI・認証・モデル・依存関係を確認する。`scripts.run_eval`と`scripts.run_loop`はClaudeに依存する。Codex/Copilotの発動精度を測定したことにはしない。
- Codex/Copilotでは、その場で利用可能かつ許可された独立実行手段を確認する。分離した実行コンテキストで比較できない場合は、独立したA/B試験とは報告しない。架空のツール・コマンド・利用量を作らない。
- 実行手段の変更で費用・入力の送信先・比較条件が変わる場合は、ユーザーへ確認してから進める。依存パッケージや別CLIは無断で導入しない。
- 成功率は実際の判定根拠から集計する。時間・トークン数は取得できた実測値だけを保存し、取得できなければ未取得とする。値を0で埋めない。
- 原文の集計・閲覧ツールは空の測定群を0と表示する場合がある。欠測を含む指標は比較対象から外し、測定できたケース数と未取得を明示する。欠測0を改善効果の根拠にしない。
- 同じコンテキストでの自己確認、形式検証、閲覧画面の起動確認、実AIによる比較評価を区別する。初回から多数のモデルや大規模な試験を必須にしない。
- 文体など主観的な品質は人間の比較レビューを使う。文字数が減ったことだけで、操作漏れが減った・品質が上がったと判定しない。

Windowsで同梱Pythonツールを使う場合は、既存の利用可能なPythonを選び、`-X utf8`と必要に応じて`-B`を付ける。原文のBashコマンドをそのままPowerShellへ貼らない。

```powershell
# このSkillのルートで実行する。いずれも外部AIを呼ばない確認例。
python -X utf8 -B scripts/quick_validate.py <対象Skillフォルダ>
python -X utf8 -B -m scripts.aggregate_benchmark --help
python -X utf8 -B eval-viewer/generate_review.py --help
```

レビュー画面は原文の`--static`で生成する。サーバー版を使う場合は使用ポートと既存プロセスを確認する。上流のサーバー起動処理にはポートを使うプロセスを終了する処理があるため、既存プロセスの終了は本人の許可を得てから行う。実際のブラウザー表示を確認した場合だけ表示確認済みと記録する。

## 4. 配置と公開用の一覧

| 種別 | 配置 |
|---|---|
| 個人共通Skill | `~/.agents/skills/<name>/SKILL.md` |
| CodexのリポジトリSkill | `.agents/skills/<name>/SKILL.md` |
| CopilotのリポジトリSkill | `.github/skills/<name>/SKILL.md`、または確認済みの`.agents/skills/` |
| Copilotの個人Agent | `~/.copilot/agents/<name>.agent.md` |
| CopilotのリポジトリAgent | `.github/agents/<name>.agent.md` |

ユーザー指定と既存管理方式を優先する。Skillの呼出元から参照スクリプト・アプリ・出力先まで確認し、ファイル単体の検証だけで接続完了としない。

この公開リポジトリのSkill/Agentを追加・変更・削除・改名したら、READMEの用途・入力・成果物・実行条件と、`scripts/install.ps1`の配布対象を確認する。隔離した`-UserHome`でpreview、`-Apply`、再previewを試し、既存の配備テストを実行する。別リポジトリでは、そのリポジトリの一覧・配布方式を使う。

## 5. 最終検証と上流差分

- `scripts/quick_validate.py`はローカル強化版を使う。UTF-8、ディレクトリ名との一致、未完了プレースホルダーも検査する。上流の許容項目に合わせて`compatibility`を許可する。上流版は比較用に`references/anthropic-quick-validate.py`へ保持する。
- 参照・スクリプトの存在、質問条件と既定値の矛盾、重複、原本と配布コピーを確認する。形式検証に通ったことと、実際の依頼に有効だったことは別に報告する。
- `agents/openai.yaml`はCodexの表示用ローカル拡張として保持する。上流の`agents/*.md`は評価用資料であり、Copilotの個人Agentへ配備しない。
- `references/upstream-provenance.json`の固定コミット・対応表・SHA-256で上流ファイルを照合する。上流由来のファイルは直接改変せず、必要な変更はここへ記録する。コード変更が必要になった場合は、理由と差分を別に記録して出典を保つ。
- 原文の更新ではLICENSE.txtと補助ファイルを含めて比較する。原文だけ新しくして補助スクリプトを旧版のまま残さない。
- 本テーラリング版の作成・検証は、評価対象Skillの実AI試験・個人配備・GitHub公開を含まない。今回実施した範囲と未実施範囲を最後に示す。
